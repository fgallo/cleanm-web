# cleanm-web

Web client for CleanM: calendar, clients, invoices and revenue for residential
cleaning businesses. It talks to the REST API in
[cleanm-api](https://github.com/fgallo/cleanm-api).

## Getting started

Requires Node 24, pinned in `.nvmrc`, and the API running locally on
`http://localhost:3000` (see its README). The API's `WEB_ORIGINS` must list
this client's dev origin, `http://localhost:5173`; its `.env.example` already
does.

```sh
nvm install
npm ci
cp .env.example .env
npm run dev
```

Then open <http://localhost:5173> and sign in as one of the two admins that
`npm run db:seed` creates in the API (`ana@example.com`, with the password in
the API's `SEED_ADMIN_PASSWORD`).

Configuration comes from `.env` (see `.env.example`): `VITE_API_URL`, the
API's origin, `http://localhost:3000` by default. Without it, `npm run dev`
and `npm run build` stop with a message. Vite inlines `VITE_*` variables into
the built files, so they are public: never put a secret there.
The session is an `HttpOnly` cookie set by the API, so every request to it is
sent with credentials.

## Layout

- `src/api/`: everything that talks to the API. `client.ts` sends JSON with
  the session cookie and turns an error response into an `ApiError` with the
  API's error shape; one module per resource (`auth.ts`) holds its request
  functions and TanStack Query options.
- `src/auth/`: the session. `RequireSession` is the layout route around every
  signed-in page: it asks `GET /auth/me`, redirects to `/sign-in` when nobody
  is signed in, and provides the session to `useSession()`.
- `src/pages/`: one component per route; `src/App.tsx` lists the routes.
- `src/components/`: shared pieces, such as the app shell. `src/components/ui/`
  is generated by the shadcn CLI (`npx shadcn@latest add <name>`) and edited
  in place.

## Tests

Vitest with Testing Library, in a jsdom environment. Tests live next to the
code they cover, as `*.test.ts(x)`. `src/test/render.tsx` renders the whole
application at a URL, and `src/test/api.ts` replaces `fetch` with invented
answers and records the requests, so no test needs the API.

```sh
npm test
```

## Scripts

| Script               | What it does                                              |
| -------------------- | --------------------------------------------------------- |
| `npm run dev`        | Starts the Vite dev server with hot module replacement    |
| `npm run build`      | Type-checks, then writes the production build to `dist/`  |
| `npm run preview`    | Serves `dist/` locally to check the production build      |
| `npm run typecheck`  | Type-checks with `tsc`, no output files                   |
| `npm run lint`       | Runs ESLint and checks formatting with Prettier           |
| `npm run lint:fix`   | Fixes what ESLint can fix and formats files with Prettier |
| `npm test`           | Runs the tests once                                       |
| `npm run test:watch` | Runs the tests again when a file changes                  |
